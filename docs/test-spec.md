# TinDog — מסמך אפיון בדיקות

## מטרה

מטרת הבדיקות היא לוודא שהמערכת עובדת באופן תקין מקצה לקצה: שהתהליכים העסקיים המרכזיים ניתנים לביצוע, שקלטים שגויים נחסמים, שהרשאות המשתמשים נשמרות, ושפעולות מרכזיות נשמרות באופן תקין במסד הנתונים.

המערכת כוללת שני סוגי משתמשים מרכזיים:
- **מאמץ (Adopter)** — מחפש כלבים, משלים פרופיל, שומר כלבים ושולח התעניינות באימוץ.
- **נציג עמותה (Shelter Admin)** — מנהל כלבים, מקבל בקשות אימוץ ומאשר או דוחה אותן.

לאחר אישור בקשת אימוץ נוצרת התאמה ונפתח צ'אט בין הצדדים.

## שכבות הבדיקה

| שכבה | כלי | מה נבדק | מיקום |
|---|---|---|---|
| Unit | Vitest | ולידציות Zod ולוגיקה טהורה של חפיסת הכלבים | `src/lib/__tests__/` |
| Component | Vitest + React Testing Library | רכיבי UI מרכזיים במנותק, באמצעות mocks | `src/components/**/__tests__/` |
| E2E | Playwright | התהליך העסקי המרכזי מול אפליקציית Next.js ו-Supabase | `e2e/main-flow.spec.ts` |
| DB / הרשאות | Supabase RLS + בדיקות ידניות/אינטגרציה | הגבלת קריאה וכתיבה לפי המשתמש ותפקידו | מדיניות RLS והמיגרציות |

## 3. התהליך העסקי המרכזי שנבדק ב-E2E

`e2e/main-flow.spec.ts` מריץ תרחיש סריאלי שמדמה שימוש אמיתי במערכת:

1. נבדקת הגנת ראוט פרטי למשתמש שאינו מחובר.
2. נציגת עמותה מתחברת ומגיעה לאזור העמותה.
3. נציגת העמותה מפרסמת כלב חדש.
4. המאמץ מתחבר ומשלים את פרופיל החובה.
5. המאמץ מסנן את החפיסה ומוצא את הכלב שנוצר בבדיקה.
6. המאמץ שולח התעניינות באימוץ.
7. נבדקת ולידציית שרת על קלט כלב שגוי.
8. נציגת העמותה רואה את הבקשה ומאשרת אותה.
9. נבדק שנוצר Match.
10. המאמץ שולח הודעה בצ'אט.
11. נציגת העמותה מתחברת, רואה את אותה הודעה ומשיבה.
12. נבדק שהתגובה מוצגת בצ'אט.

לצורך יציבות הבדיקה, נעשה שימוש בחשבונות הדמו הקיימים:
- `maya@demo.tindog.app` — נציגת עמותה.
- `alex@demo.tindog.app` — מאמץ.

כך תהליך ה-E2E המרכזי אינו תלוי בשירות שליחת אימייל חיצוני לצורך אימות חשבון חדש.

## 6. בדיקות UI בסיסיות

נבדקים בין היתר:
- הודעות שגיאה נגישות עם `role="alert"`.
- כפתורים וטפסים מתנהגים באופן תקין בזמן פעולה.
- כרטיסי כלבים מציגים את פרטי הכלב.
- קרוסלת התמונות מתנהגת בהתאם למספר התמונות.
- כרטיסי בקשות מציגים את פרטי המאמץ והכלב.
- הודעות הצלחה ושגיאה מוצגות באופן מובחן.
- דפי המערכת תומכים בזרימת משתמש ברורה לפי התפקיד.

בנוסף בוצעה בדיקה ידנית של הממשק בדפדפן ובתצוגות מסך שונות במהלך הפיתוח.
