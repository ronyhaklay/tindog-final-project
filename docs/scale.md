# TinDog — מסמך סקייל בסיסי

## מה יקרה עם עשרות או מאות משתמשים

הארכיטקטורה הנוכחית (Vercel serverless + Supabase managed Postgres) מטפלת במאות משתמשים פעילים ללא שינוי:

- **Frontend/SSR** — Vercel מרים instance לכל בקשה; אין state בשרת ולכן אין צוואר בקבוק ב-scale אופקי.
- **Database** — ה-Free tier של Supabase מספק בסיס נתונים ייעודי; העומסים שלנו (שאילתות קצרות ממופתחות) רחוקים מהגבולות שלו.
- **תמונות** — מוגשות ישירות מ-Supabase Storage CDN, לא דרך השרת שלנו, ומועברות דרך אופטימיזציית התמונות של Next.js.

## שאילתות כבדות פוטנציאליות והפתרון

| שאילתה | הבעיה הפוטנציאלית | הפתרון שמומש |
|---|---|---|
| חפיסת ההחלקה | `NOT EXISTS` על טבלת swipes שגדלה מהר | אינדקס `swipes(swiper_id, dog_id)` הופך את הבדיקה ל-index lookup; אינדקס `dogs(listing_type, city, is_active, created_at)` מסנן ביעילות; `LIMIT 10` |
| היסטוריית צ'אט | שיחה ארוכה עם אלפי הודעות | אינדקס `messages(request_id, created_at)` + טעינת 50 ההודעות האחרונות בלבד |
| בקשות ממתינות (badge) | ספירה בכל טעינת עמוד | `count: exact, head: true` — ספירה ללא שליפת שורות, על אינדקס `match_requests(dog_id, status)` |

## אינדקסים

כל האינדקסים מוגדרים במיגרציה (`supabase/migrations/0001_init.sql`), תואמים אחד-לאחד לדפוסי הגישה: חפיסה, בקשות לפי כלב/מבקש, הודעות לפי שיחה, תמונות לפי כלב.

## הימנעות מטעינה מיותרת של מידע

- **Pagination בחפיסה** — נטענים 10 כלבים בכל פעם; רענון אוטומטי כשנשארים 3 קלפים.
- **הודעות** — 50 אחרונות בלבד; הודעות חדשות מגיעות ב-Realtime push במקום polling.
- **החלקה אופטימית** — ה-UI ממשיך מיד; הכתיבה נעשית ברקע ואינה חוסמת את המשתמש.
- **`get_swipe_deck` כ-RPC אחד** — כלב + תמונות + שם בעלים בשאילתה אחת במקום N+1.
- **תמונות** — `next/image` עם `sizes` מדויק; רק התמונה הנוכחית בקרוסלה נטענת בעדיפות.

## הפרדה בין צד לקוח וצד שרת

- כל הכתיבות עוברות Server Actions בצד שרת — הלקוח לעולם לא כותב ישירות לטבלאות.
- חריג מכוון: העלאת תמונות נעשית מהדפדפן ישירות ל-Storage כדי שה-serverless function לא תעביר מגה-בייטים של קבצים (חוסך זמן ריצה וכפוף למדיניות RLS של Storage).
- קריאת נתונים נעשית ב-Server Components — ללקוח מגיע HTML מוכן, בלי waterfalls של fetch.

## מגבלות קיימות

1. **אין אינדקס גיאוגרפי** — סינון עיר הוא `ILIKE`; מספיק לעשרות אלפי כלבים אך לא לחיפוש "בקרבתי" אמיתי.
2. **חפיסה נטענת מחדש בכל שינוי פילטר** — אין cache בין פילטרים.
3. **Realtime connection לכל טאב צ'אט פתוח** — בסדרי גודל גדולים נדרש ניהול חיבורים.
4. **ספירת ה-badge רצה בכל ניווט** — אפשר להעביר ל-Realtime subscription.

## שיפורים לגרסה עתידית

- PostGIS + אינדקס גיאוגרפי לחיפוש לפי מרחק אמיתי.
- Cursor-based pagination גם לרשימת ההתאמות וההודעות (infinite scroll).
- Redis/Edge cache לחפיסות פופולריות (למשל כלבי עמותות).
- תמונות בגדלים מרובים (thumbnails) שנוצרים ב-upload עם Storage transformations.
- Rate limiting ברמת ה-API (למשל Vercel Firewall או Upstash) למניעת swipe bots.
