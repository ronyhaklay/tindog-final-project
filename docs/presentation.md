# TinDog — מתווה הצגה (10–15 דקות)

## 1. המוצר והבעיה (2 דק')

- דמו פתיחה: 30 שניות של החלקה חיה באפליקציה (הכי משכנע).
- הבעיה: מציאת בית לכלבים מפוזרת ולא אישית; קשה למצוא חברים מתאימים לכלב.
- הפתרון: פרופיל אישיות לכל כלב + מנגנון swipe מוכר. סוג מודעה אחד מאחד אימוץ/אומנה/פלייטדייט.

## 2. משתמשים וערך עסקי (1.5 דק')

- שני צדדים: מפרסמי כלבים ומחפשים; אותו משתמש יכול להיות בשניהם.
- ערך: קיצור זמן המתנה לאימוץ, התאמות טובות יותר, קהילה עם שימוש חוזר.
- לקוחות עתידיים: עמותות (מנוי), עסקים לכלבים (פרסום).

## 3. דמו התהליך המרכזי (3 דק')

1. משתמש א' מפרסם כלב לאימוץ (טופס + העלאת תמונות)
2. משתמש ב' מסנן, מחליק ימינה
3. משתמש א' מאשר את הבקשה ב-Requests
4. צ'אט בזמן אמת (להראות בשני חלונות זה לצד זה!)

## 4. ארכיטקטורה (2 דק')

- Next.js App Router על Vercel: Server Components לקריאה, Server Actions לכתיבה.
- Supabase: Postgres + Auth + Storage + Realtime.
- להראות את הדיאגרמה מ-technical-design.md.
- הדגשים: אין REST ידני — Server Actions עם Zod; העלאת תמונות ישירות מהדפדפן ל-Storage.

## 5. בסיס הנתונים (2 דק')

- 6 טבלאות: profiles, dogs, dog_photos, swipes, match_requests, messages.
- החלטות מעניינות להסביר:
  - `listing_type` על הכלב — מודל אחד לשני מקרי שימוש.
  - `swipes` עם UNIQUE — "לא רואים כלב פעמיים".
  - RPC `get_swipe_deck` — שאילתת החפיסה כולה בדאטהבייס (NOT EXISTS ממופתח).
  - RPC `record_swipe` — החלקה + בקשה בטרנזקציה אחת.
  - טריגר שיוצר profile בהרשמה.

## 6. בדיקות (1.5 דק')

- פירמידה: 37 בדיקות Vitest (ולידציות, לוגיקת חפיסה, קומפוננטות) + E2E Playwright שמריץ את כל התהליך העסקי עם שני משתמשים אמיתיים.
- להראות את main-flow.spec.ts רץ (או הקלטה).

## 7. אבטחה (1.5 דק')

- שתי שכבות: middleware לניתוב + RLS בדאטהבייס על כל טבלה.
- דוגמה חיה טובה: לנסות לעדכן כלב של משתמש אחר ב-SQL — 0 שורות.
- צ'אט נפתח רק לבקשה מאושרת — נאכף ב-RLS, לא רק ב-UI.
- session ב-HTTP-only cookies; סודות ב-env vars בלבד.

## 8. סקייל (1 דק')

- אינדקסים לפי דפוסי הגישה (חפיסה, צ'אט, בקשות).
- Pagination בחפיסה ובצ'אט; Realtime במקום polling; תמונות מ-CDN.
- מגבלות ומה היינו משפרים: PostGIS לחיפוש גיאוגרפי, rate limiting, signed URLs.

## 9. מה היינו משפרים עם עוד זמן (0.5 דק')

- התראות push, דיווח/חסימה, חיפוש לפי מרחק, אימות עמותות, אפליקציית מובייל.

## טיפים להצגה

- להתאמן על הדמו עם נתוני seed מוכנים (`npm run seed`).
- להכין שני דפדפנים מחוברים מראש (בעלים + מאמץ) לדמו הצ'אט.
- להיות מוכנים לשאלות "ראיון": למה Server Actions ולא REST? מה זה RLS? למה RPC לחפיסה? איך עובד ה-Realtime?
